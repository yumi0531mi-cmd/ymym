# KIS API 호출 보호 규칙

## 목적

이 앱은 저장된 `KIS_ACCESS_TOKEN`만 사용하며, Community Cloud에서 자동 토큰 발급을 기본적으로 차단한다. 토큰 발급 제한과 별개로 시세·호가·분봉 REST API에도 호출 유량 제한이 있을 수 있으므로, 앱 내부에서 더 보수적인 요청 예산을 적용한다. 실제 KIS의 API별 상한은 변경될 수 있으므로 앱의 값은 공급자 제한을 보장하거나 대체하지 않는 안전 여유값이다.

| 동작 | KIS 요청 수 | 계산 근거 |
|---|---:|---|
| 앱 첫 화면만 열기 | 0건 | 종목 분석 전에는 시세 호출 함수를 실행하지 않음 |
| 선택 종목 분석 | 최대 3건 | 현재가 1건 + 1호가 1건 + 1분봉 1건 |
| 국내 시작목록 빠른검색 | 14건 | 시작목록 14개 종목의 현재가 |
| 미국 시작목록 빠른검색 | 21건 | 시작목록 21개 종목의 현재가 |
| 60초 자동 새로고침 | 분당 최대 3건 | 현재가·1호가 2건 + 1분봉 1건 |
| 60초 자동 새로고침 5시간 | 최대 900건 | 분당 3건 × 300분 |

## 기본 보호값

| 환경 변수 | 기본값 | 역할 |
|---|---:|---|
| `KIS_ALLOW_TOKEN_ISSUE` | `false` | Community Cloud 자동 토큰 발급 차단 |
| `KIS_MIN_REQUEST_INTERVAL_SECONDS` | `1.0`초 | 동일 앱 프로세스 내 요청 사이 최소 간격 |
| `KIS_MAX_REQUESTS_PER_MINUTE` | 30건 | 최근 60초 rolling 예산 |
| `KIS_MAX_REQUESTS_PER_FIVE_HOURS` | 1,100건 | 최근 5시간 rolling 예산 |
| `KIS_MAX_RETRIES` | 1회 | 네트워크 오류의 제한된 재시도 |

모든 REST 요청과 재시도는 전송 전에 예산에 포함한다. 최근 1분 또는 5시간 예산을 다 쓰면 요청을 보내지 않고 대기 시간과 함께 차단한다. KIS가 HTTP 429와 `Retry-After`를 반환하면 앱도 그 시간만큼 추가 요청을 차단한다.

자동 새로고침은 60·120·300초 중에서만 선택할 수 있다. 60초는 5시간 기준 900건이며, 남은 예산은 시작목록 검색·수동 재분석·실패한 요청의 제한적 재시도에 사용한다. 화면의 `KIS 호출 보호` 수치는 현재 Community Cloud 앱 프로세스의 rolling 사용량이다. 앱 재시작 후에는 로컬 메모리 카운터가 초기화되므로, KIS의 실제 계정별 제한보다 항상 더 낮게 설정해야 한다.

> 이 보호 장치는 과도한 호출을 줄이는 운영 안전장치이며, KIS의 API별·계정별 실제 유량 상한을 보장하지 않습니다. API 응답의 429 및 안내 문구를 우선 기준으로 삼습니다.
