# 전체 경로 검증 승률 분석 실행 안내

이 문서는 스캐너가 Supabase에 저장한 `validation_case` 기록을 분석하는 방법입니다. 분석용 SQL은 같은 폴더의 [`supabase_full_path_validation_analytics.sql`](supabase_full_path_validation_analytics.sql)에 있습니다.

> **판정 원칙:** 5·10·15·30분 예측이 모두 통과하고, 현재가·장세·구조 목표·체결 가능성·1차 목표 선도달 조건까지 충족한 기록만 `엄격 전체 통과`로 계산합니다. 완료된 전체 경로 표본이 100건 미만이면 80% 통과 여부를 확정하지 않습니다.

| 실행 순서 | Supabase에서 할 일 | 무엇을 보는가 |
|---|---|---|
| 1 | 왼쪽의 **SQL Editor**를 누릅니다. | 쿼리를 실행할 화면을 엽니다. |
| 2 | SQL 파일에서 원하는 번호의 쿼리 **한 개만** 복사해 붙여넣고 **Run**을 누릅니다. | 쿼리 결과 표가 나옵니다. |
| 3 | 먼저 **1번**을 실행합니다. | 전체 완료 표본 수, 전체 경로 통과율, 엄격 통과율, 100건·80% 판정을 봅니다. |
| 4 | 80% 기준을 못 채우면 **4번**을 실행합니다. | 현재가·체결·구조 목표·경로·장세·목표 선도달 중 실패가 많은 원인을 봅니다. |
| 5 | 개선 전후 비교에는 **2번**과 **3번**을 실행합니다. | 시장·세션·전략별, 5·10·15·30분별 성적을 비교합니다. |

## 쿼리별 목적

| 번호 | 이름 | 사용 시점 |
|---:|---|---|
| 1 | 전체 요약 | 가장 먼저 실행합니다. 100건·80% 충족 여부를 확인합니다. |
| 2 | 시장·세션·전략별 성적 | 어느 시장·세션·전략 조합이 실제로 통과하는지 비교합니다. |
| 3 | 5·10·15·30분별 성적 | 어느 예상 시간이 전체 경로 실패를 가장 많이 만드는지 확인합니다. |
| 4 | 실패 원인 | 통과율이 낮을 때 수정 우선순위를 정합니다. |
| 5 | 최근 100건 원본 감사 | 기준을 바꾸거나 기록을 숨기지 않고 원본을 직접 점검합니다. |

## 결과 해석

`완료된 전체 경로 표본 수`가 100건 미만이면 결과는 참고용입니다. 100건 이상일 때 `엄격 전체 통과 수`가 80건 이상이고, 엄격 전체 통과율이 80% 이상이며 비용 반영 평균 수익률이 양수인 경우에만 쿼리는 `80% 전체 경로 기준 통과`로 표시합니다. 이 조건을 만족하지 못하면 4번 실패 원인 쿼리의 비중이 높은 항목부터 수정 대상으로 봅니다.

`엄격 전체 통과`는 단순히 목표가에 닿은 사례 수가 아닙니다. 완료된 5·10·15·30분 경로, 현재가 교차검증, 장세 판정, 구조적 목표, 체결 가능성, 1차 목표와 손절가의 시간상 선후 관계를 모두 반영합니다.
